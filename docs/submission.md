# Project Submission Form

Final submissions go through the event portal's **Project Submission** form. It starts in **Draft · Not submitted** status.

## Fields
| Field | Type | Notes / what we prepare |
|---|---|---|
| **Addressing Use Cases** | Selected from an event-provided list | The list of use cases isn't known yet. Pick every case the project really serves; this helps Scalability (20%). |
| **Using Datasets** | Selected from an event-provided list | The list of datasets isn't known yet. Must match the project's `docs/disclosure.md`. |
| **Project Name** | Text | |
| **Project Description** | Markdown (Write/Preview tabs) | Draft it in the project's `docs/submission-description.md`, then paste it in. Structure it around the judging criteria (template below). |
| **Repository URL** | URL (e.g. GitHub) | Needs a clean repo with a README. |
| **Demo URL** | URL | Needs a hosted or recorded demo (video link works if hosting is not possible). |
| **Presentation URL** | URL (e.g. Google Slides) | Slide deck link. |

## Description template (paste-ready Markdown)
```markdown
## Problem
Who (rating/watch station), current process, measured burden.

## Solution
What it does, in one paragraph. Key features.

## Impact (Warfighting & Deckplate)
Before/after numbers: time saved, steps removed, errors avoided.

## Speed to Fleet
Runs offline / DDIL. How it installs. Fielding steps.

## Scalability
Other ship classes, ratings and domains it serves. Config-driven.

## Barriers Removed
Manual entry eliminated. Friction we hit (see friction log).

## Human Authority & Safety
Approval points, prohibited actions, stop/shutdown, audit log.

## OSW ROI Alignment
Which ROIs this delivers on, with evidence (skills developed, platform adoption, friction documented, innovation, learning under contested conditions).

## Next Steps (30/60/90)
Mission owner, technical owner, next experiment, resources needed.

## Disclosure
Models, APIs, datasets, services used. Prior work vs. built at the event.
```
